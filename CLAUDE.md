# CLAUDE.md

OpenLanguageKit, the knowledge layer behind the OpenLangKit site (openlangkit.space): curriculum (schema v2, en/ja/zh), pedagogical primitives, building blocks, blueprint planner, pedagogy graph. No dependencies. Course content and canonical docs are in Chinese; each public doc has an English version (`*.en.md`, `README.md` is English and `README.zh-CN.md` Chinese) that must be updated in the same change. The website lives in a separate site repo that keeps no copy of these files: its Vercel build clones this repo and runs `scripts/sync-knowledge.py`, and `.github/workflows/check-and-publish.yml` here triggers that build after the checks pass (secret `SITE_DEPLOY_HOOK`). This repo is the single source of truth.

- After any change run `sh check.sh` (rebuilds generated files, runs every validator; all must report 0 errors).
- Generated, never hand-edit: `curriculum/<lang>/graph.json`, `coverage.md`, `dist/data.js`, `blueprint/science.js`, `curriculum/primitives/coverage.md`.
- The two READMEs open with pictures generated by `python3 assets/readme/make.py` (English in `assets/readme/`, Chinese in `assets/readme/zh/`). The counts in those pictures and in the README tables (knowledge points, practice types, pages, tracks) are written by hand: update `NUM` in `make.py`, rerun it, and fix the tables when the numbers change. README links to the live site use `https://www.openlangkit.space`.
- Languages: `curriculum/<code>/` for en, ja, zh (explained in Chinese) and, since 2026-11-17, es and fr (A1–A2 only, explained in English: `path.json` has `"instructionLang": "en"`, examples are `{es, en}` / `{fr, en}`). Validators and `check.sh` pick up every `curriculum/*/kcs.json`. Track ids must be unique across languages (prefix new ones, e.g. `es-child`) and each needs an entry in `blueprint/profiles.json`. A new language starts from its official framework as the denominator; see the es/fr section of `curriculum/SCHEMA.md`.
- Teaching by age, workflows, pictures (all in `curriculum/primitives/`, each a Chinese original plus a `.en.json` with identical keys, checked by `primitives/check.py`): `age-bands.json` (three bands child / youth / adult, 11 do-avoid dimensions each with `basis` literature or design_inference and `refs` into `pedagogy/graph.json`, plus `variants` for all 56 primitives with `fit` core / adapt / defer); `workflows.json` (primitives arranged into one activity for a scenario; picture-book reading has two, learning to read vs reading to learn); `image-roles.json` (eight teaching roles for a picture, what it must show, whether it may be generated, placement per band). `blueprint/image-brief.js` writes an image-model prompt and acceptance checklist from a role; it calls no service. The planner puts `ageBand` and per-primitive `ageVariant` into the blueprint; ages are `5-7 | 8-12 | 13-17 | 18-22 | adult`. `build.py` bundles the three files into `window.PRIMITIVES` (`ageBands`, `workflows`, `imageRoles`).
- `curriculum/primitives/age-design.json` (+ `.en.json`) is the operationalisation of age: ten constructs, each a chain *research claim → how we read it and its limits → design variables with a value per band and a layer (kc | plan | block) → measures (source `block` = from the page's evidence events, `host` = the hosting app must record it)*; `layers` says what stays and what changes on each layer; `planDefaults` are the per-band scheduling assumptions the planner uses; `blocks.<slug>.rows` state, per block, which variables that page really changes (child/youth/adult, or child/default for blocks with only `variant=child`). Write a row only for what the page does. `build.py` generates `blocks/age-design.js` (`window.KT_AGE`, both languages; do not edit), and `KTBlock.ageWhy(slug, band)` in the runtime renders the "how this version differs, and why" panel from it. The planner emits `blueprint.ageDesign`. Not every block needs age versions: add them only where the difference is substantive, and document each in `blocks`.
- `blueprint/image-brief.js` returns `trace` (each prompt sentence with why it is there, the rule it comes from and `ped:` refs) and, given `--workflow`/`--step`, `timing` (when the picture is used and what it must do then, from `media.pictureWhy` in `workflows.json`); `--explain` prints it readably. Nothing here generates images.
- New blocks take `?band=child|youth|adult`. `space-3d` loads Three.js r128 from cdnjs with a 2D fallback; it is the only block that touches the network.
- Read first: `curriculum/SCHEMA.md` (data model), `curriculum/primitives/README.md`, `blocks/README.md`, `BLUEPRINT.md` (keep it in sync when blueprint fields or invariants change).
- `source-units.json` is the denominator: never drop or invent rows. `verification` must reflect what was actually read. JLPT grammar levels are editorial estimates. Don't fabricate URLs or page numbers.
- Primitive `implementations[]` are `{asset}` (asset-library id) or `{artifact}` (id in `blocks/registry.js`). A block covers a KC only if its registry artifact lists that KC.
- Blocks have a Chinese and an English interface: `blocks/runtime/block.js` picks it (`?lang=` → `localStorage['atlas-lang']` → browser language) and gives `KTBlock.L(zh, en)` for interface strings and `KTBlock.t(obj, key)` for data-pack text, which reads the parallel English field (`xEn` beside `x`, `en` beside a `zh` gloss) and falls back to the Chinese. Chinese is the source; add the English in the same change. Never translate the language being taught. `registry.js` carries `titleEn` / `doesEn` / `noteEn`; `KTCatalog` takes `lang`. See `blocks/README.md`.
- Blocks stay self-contained (`blocks/runtime/block.css` mirrors the site palette). No KanjiVG / Make Me a Hanzi data. Uncertain items go in a pack's `review` list.
- Since 2026-11-12 every formerly `spec` primitive has its own block (now 32 blocks, 106 packs, 126 artifacts; `primitives.en.json` is the English version of the contracts, shape-checked against `primitives.json` by check.py and written by build.py to `dist/primitives-en.js`, which overlays `window.PRIMITIVES` on a page shown in English; the planner takes `outLang` (`--out-lang en|zh`, default = the course's instruction language); shared icons are `KTBlock.icon(name, label)` — no emoji as interface icons; Spanish and French packs live in their own files `blocks/data/<slug>-es.js` / `-fr.js`; including `picture-book` and `space-3d` added 2026-11-17; file name = primitive slug, e.g. `blocks/slot-order.html` + `blocks/data/slot-order.js`). All 24 new ones are `partial`: `blocks/GAPS.md` lists what each page does not do from its contract and what awaits native-teacher review. No primitive is `spec` now; 23 are still `implemented-en` (pages only in the external asset library). Thumbnails: `sh blocks/thumbs/make.sh`.
- `pedagogy/` uses the `ped:` namespace and is maintained independently; don't merge it into curriculum data.
- Paths that the site depends on (changing them breaks its sync): `dist/data.js`, `blocks/**`, `blueprint/planner.js`, `blueprint/science.js`, `curriculum/<lang>/graph.json`, `curriculum/primitives/primitives.json`.
